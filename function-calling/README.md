# function-calling

Part of the [ProjAtlas](../) code repository. Code and data for training and evaluating
the fine-tuned function-calling model behind ProjAtlas's neuron selection and brain
visualization agents (see paper Methods: "Function calling model training and evaluation").

We fine-tune [Salesforce xLAM-2-8b-fc-r](https://huggingface.co/Salesforce/Llama-xLAM-2-8b-fc-r) with LoRA supervised fine-tuning (SFT) on a domain-specific neuroscience tool-use dataset. The resulting model significantly improves function-calling accuracy across three neuroscience visualization tools (Mouse, Macaque, Neuroviz) and three task types (Zero, Single, Parallel).

The fine-tuned LoRA adapter weights are published separately on Hugging Face at
**[zhang-manyi/ProjAtlas-xLAM2-8B-FunctionCalling-lora](https://huggingface.co/zhang-manyi/ProjAtlas-xLAM2-8B-FunctionCalling-lora)**:

```bash
huggingface-cli download zhang-manyi/ProjAtlas-xLAM2-8B-FunctionCalling-lora --local-dir ./saves/xlam-8b/lora/sft
```

See ["Fine-Tuned Model Weights"](#fine-tuned-model-weights) below for licensing and scope
notes. This repository contains the training/evaluation code, the dataset, and the raw
evaluation outputs used to produce the paper's Table 3.

## Results

Held-out test set, 865 samples (from Extended Data Table 3 in the paper):

|          | Zero          | Single         | Parallel       | Total           |
|----------|---------------|----------------|----------------|-----------------|
| Mouse    | 15/16 (93.8%) | 81/82 (98.8%)  | 33/34 (97.1%)  | 129/132 (97.7%) |
| Macaque  | 14/14 (100.0%)| 95/95 (100.0%) | 30/30 (100.0%) | 139/139 (100.0%)|
| Neuroviz | 64/65 (98.5%) | 279/284 (98.2%)| 236/245 (96.3%)| 579/594 (97.5%) |
| **Total**| 93/95 (97.9%) | 455/461 (98.7%)| 299/309 (96.8%)| **847/865 (97.9%)** |

Full per-model results (base model, fine-tuned model, and five general-purpose LLM
baselines) are in [`results/`](results/).

## Installation

This project uses [LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory) as the training backend.

**Tested environment:** Python 3.11.14, PyTorch 2.10.0+cu128, CUDA 12.8
**LLaMA-Factory commit:** `ea644d04ecfc26bb6ad372767c3e561113d46de4`

### 1. Install LLaMA-Factory

Clone LLaMA-Factory at the tested commit and set up the environment by following the [official installation guide](https://github.com/hiyouga/LLaMA-Factory?tab=readme-ov-file#installation). Make sure the environment is working before proceeding.

```bash
git clone https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory
git checkout ea644d04ecfc26bb6ad372767c3e561113d46de4
```

### 2. Place this directory alongside (or symlink it into) the LLaMA-Factory root

This `function-calling/` directory is part of the ProjAtlas monorepo; it is not cloned
standalone. Copy or symlink it next to your LLaMA-Factory checkout, e.g.:

```bash
# From inside the LLaMA-Factory directory
cp -r /path/to/ProjAtlas/function-calling ./function-calling
cd function-calling
```

### 3. Register the datasets

Copy the dataset files and registry into LLaMA-Factory's `data/` directory:

```bash
cp data/*.json ../data/
# Merge dataset_info.json entries into ../data/dataset_info.json
```

Or simply run all scripts from inside this directory — the paths in the configs assume LLaMA-Factory is the parent directory.

### 4. (Optional) Set up API keys for API model evaluation

```bash
cp api_config.json.example api_config.json
# Edit api_config.json and fill in your API keys
```

## Training

> To download the model from ModelScope instead of Hugging Face, prefix any command below with `USE_MODELSCOPE_HUB=1`.

### Single GPU

```bash
llamafactory-cli train xlam_lora_sft_8b.yaml

# ModelScope
USE_MODELSCOPE_HUB=1 llamafactory-cli train xlam_lora_sft_8b.yaml
```

### Multi-GPU

```bash
# Adjust CUDA_VISIBLE_DEVICES to match your available GPUs
CUDA_VISIBLE_DEVICES=0,1 llamafactory-cli train xlam_lora_sft_8b.yaml

# ModelScope
USE_MODELSCOPE_HUB=1 CUDA_VISIBLE_DEVICES=0,1 llamafactory-cli train xlam_lora_sft_8b.yaml
```

### Background (with logging)

```bash
bash train.sh
```

The training config (`xlam_lora_sft_8b.yaml`) uses:
- Base model: `Salesforce/Llama-xLAM-2-8b-fc-r`
- Method: LoRA (rank=8, target=all)
- Epochs: 3, LR: 1e-4, cosine schedule
- Precision: bf16

## Evaluation

All evaluation scripts save results to `results/` by default.

### 1. Base model (baseline, no LoRA) — requires LLaMA-Factory

```bash
# Run from LLaMA-Factory root directory
PYTHONPATH=. CUDA_VISIBLE_DEVICES=0 python function-calling/eval_custom.py \
    --model_name_or_path Salesforce/Llama-xLAM-2-8b-fc-r \
    --hub modelscope \
    --adapter_path "" \
    --dataset_path function-calling/data/test.json \
    --template auto \
    --num_print -1 \
    --output_dir function-calling/results
```

### 2. Fine-tuned model (LoRA) — requires LLaMA-Factory

Download the LoRA adapter as shown at the top of this README (or see
["Fine-Tuned Model Weights"](#fine-tuned-model-weights)), then:

```bash
# Run from LLaMA-Factory root directory
PYTHONPATH=. CUDA_VISIBLE_DEVICES=0 python function-calling/eval_custom.py \
    --model_name_or_path Salesforce/Llama-xLAM-2-8b-fc-r \
    --hub modelscope \
    --adapter_path function-calling/saves/xlam-8b/lora/sft \
    --dataset_path function-calling/data/test.json \
    --template auto \
    --num_print -1 \
    --output_dir function-calling/results
```

Output files: `results/xlam_8b_finetuned_predictions.json`, `_metrics.json`, `_bad_cases.json`

### 3. API models (GPT, Claude, Gemini, etc.) — standalone

Supported providers and models:

| Provider | Model |
|----------|-------|
| `openai` | `gpt-5.4` |
| `anthropic` | `claude-sonnet-4-6` |
| `google` | `gemini-3.1-pro-high` |
| `qwen` | `qwen2.5:72b` (local Ollama, port 11436) |
| `llama` | `llama3.3` (local Ollama, port 11436) |

```bash
# Single provider
python eval_api_models.py \
    --provider openai \
    --prompt_strategy unified \
    --dataset_path data/test.json

# Batch: all providers × all strategies
bash run_all_api_evaluations.sh
```

Supported prompt strategies: `unified` | `optimized` | `fewshot`

To run multiple providers in parallel, open separate terminals:

```bash
# Terminal 1
python eval_api_models.py --provider openai --prompt_strategy unified --dataset_path data/test.json

# Terminal 2
python eval_api_models.py --provider anthropic --prompt_strategy unified --dataset_path data/test.json
```

If some samples fail due to API errors, retry them after the main run completes. The retry loop runs up to 10 rounds, merging successful results each round until all samples are recovered:

```bash
# Retry failed samples for openai
python eval_api_models.py \
    --provider openai \
    --prompt_strategy unified \
    --retry_failed results/openai_gpt-5.4_unified_failed.json \
    --merge_results results/openai_gpt-5.4_unified_predictions.json

# Retry failed samples for anthropic
python eval_api_models.py \
    --provider anthropic \
    --prompt_strategy unified \
    --retry_failed results/anthropic_claude-sonnet-4-6_unified_failed.json \
    --merge_results results/anthropic_claude-sonnet-4-6_unified_predictions.json
```

If any samples still fail after 10 rounds, they are saved back to `_failed.json` and can be retried again with the same command.

```
       Mouse   15/16  (93.8%)   81/82  (98.8%)   33/34  (97.1%)  129/132 (97.7%)

---------------------------------------------------------------------------------
       Total   93/95  (97.9%)  455/461 (98.7%)  299/309 (96.8%)  847/865 (97.9%)

```

**Evaluation dimensions:**
- **Dataset type** (inferred from tool names in `input`): Mouse / Macaque / Neuroviz
- **Task type** (inferred from number of function calls in `output`): Zero / Single / Parallel

**Evaluation rules:**
- Zero: model output is NOT valid JSON → correct
- Single / Parallel: parse both prediction and target as JSON, compare semantically

The LoRA adapter fine-tuned for this paper is published on Hugging Face:

> **Scope note:** this adapter is fine-tuned specifically on the ProjAtlas platform's own
> function-calling tool schema (neuron selection and brain-visualization commands, see

> general-purpose function-calling model and will not perform well on tool schemas outside

## Local Deployment with vLLM

The fine-tuned model is deployed in ProjAtlas via [vLLM](https://github.com/vllm-project/vllm),
serving the merged full model (see "Merge LoRA Weights" above).

### 1. Install vLLM

```bash
pip install vllm
```

### 2. Serve the merged model

```bash
vllm serve function-calling/output/merged_Llama-xLAM-2-8b-fc-r \
    --served-model-name xlam-8b-finetuned \
    --tool-call-parser xlam \
    --chat-template function-calling/output/merged_Llama-xLAM-2-8b-fc-r/chat_template.jinja \
    --enable-auto-tool-choice
```

`--tool-call-parser xlam` and `--chat-template` are required for vLLM to correctly parse
this model's function-calling output format. This starts an OpenAI-compatible API server
(default `http://localhost:8000/v1`).

### 3. Query the server

```bash
curl http://localhost:8000/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
      "model": "xlam-8b-finetuned",
      "messages": [{"role": "user", "content": "Start with mouse line Pdyn."}],
      "tools": [{"type": "function", "function": {"name": "set_mouse_line", "parameters": {"type": "object", "properties": {"mouse_line": {"type": "string"}}}}}]
    }'
```

## Data Format

Training data uses the Alpaca format:

```json
[
  {
    "instruction": "Start with mouse line Pdyn.",
    "input": "tools: [{\"type\": \"function\", \"function\": {\"name\": \"set_mouse_line\", ...}}]",
    "output": "[{\"name\":\"set_mouse_line\",\"arguments\":{\"mouse_line\":\"Pdyn\"}}]"
  }
]
```

- `instruction`: user utterance
- `input`: available tools in JSON format (prefixed with `tools: `)
- `output`: expected function call(s) as a JSON array, or plain text for Zero tasks
